# CAPS Customer Frontend — Requirement Traceability

Source of truth: _MINI_PROJECT_I_CAPS_SRS.pdf_. Visual reference: _Customer_Login_merged.pdf_.
This phase covers **only the customer frontend**. Status values:

- **FE** – implemented and working in the browser
- **LOCAL** – local validation, preferences, or non-authoritative estimates are available without a backend
- **BE** – needs a backend that doesn't exist yet; the screen shows the right state but the capability itself isn't delivered
- **OOS** – out of scope for the customer app
- **NI** – not implemented

Verification: **U** = unit test (`src/caps/lib/rules.test.js`), **B** = Playwright browser walkthrough at 390, 320 and 1280 px (results below), **R** = code review only.

## Frontend assumptions (not SRS requirements)

| #   | Assumption                                                                                                                                                                       | Where configured                           |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| A1  | GST rate 18%                                                                                                                                                                     | `src/caps/lib/config.js` `GST_RATE`        |
| A2  | Price = pages in range × copies × per-page rate (by paper and colour) + binding × copies + urgent surcharge. Double-sided is charged per printed page, the same as single-sided. | `lib/pricing.js`, backend-provided rates |
| A3  | Custom range syntax `1-3,5`, ascending ranges, within the page count, duplicates merged                                                                                          | `lib/validation.js`                        |
| A4  | Page count: read from PDF page objects when possible, otherwise estimated from file size. The user can edit it.                                                                  | `services/uploadService.js`                |
| A5  | Cancellation only in `pending_payment` or `queued`                                                                                                                               | `config.js` `CANCELLABLE_STATUSES`         |
| A6  | 25 MB file limit (from the mockup)                                                                                                                                               | `config.js`                                |
| A7  | GST is applied after the urgent surcharge                                                                                                                                        | `lib/pricing.js`                           |
| A8  | Printer selection is not shown to customers                                                                                                                                      | —                                          |
| A9  | Wait = queue length × shop average minutes per job                                                                                                                               | `lib/queue.js`                             |

Other gaps: support contact details, the final legal text and the real shop list weren't provided, so the app uses placeholders.

## Test results (actual, 15 Oct 2026)

- `npm test -- --run`: **26/26 passed** across 4 test files, including focused auth/payment safeguard tests.
- `npm run lint`: passed with 6 existing Fast Refresh warnings in template `src/components/ui/*.tsx` files and no errors.
- `npm run build`: passed in the approved environment; client, SSR and Nitro output compiled successfully. Vite reported informational configuration/build warnings only.
- Focused service tests verify temporary sign-in never persists a password and order/payment mutations are blocked until the backend is connected.
- Browser walkthrough: **blocked**. The available browser surface reported no browsers or tabs, so the local dev server was not used for an interactive walkthrough.
- Not tested: real devices, screen readers, Safari/iOS, the full interactive flow, timing with real first-time users (NFR 8.5), real backend integrations and production security controls.
